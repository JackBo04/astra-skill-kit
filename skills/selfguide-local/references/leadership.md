# 网页主导，Codex 执行

## 职责和信息补充

网页版是主要指导者和正文作者，负责总体方案、关键技术选择、证据需求、下一步行动、写作与验收。正文起草、翻译、润色和实质改写按 [写作模块](../modules/writing.md) 交给网页版，Codex 按需补充背景和材料，协助保存与排版。Codex 是执行者，负责读取实际环境和文件、采集日志与数据、执行命令或修改、独立验证、上传选定材料并反馈。这里的“本地 Codex”指当前执行端，仍在用户选择连接的服务器工作，不因此迁移任务到用户电脑。

开始实质实现前，把用户原始任务、已知约束、资源和完成标准交给网页版，请它先明确缺失信息与首批可执行步骤。不要先自行确定全部方案、只在最后让网页盖章。

网页版缺失的信息由它主动向 Codex 提出。请它把需求编号，说明需要哪个文件、哪些字段、什么日志范围或哪项实验，以及用途。Codex 按编号从现场获取，逐项提供实际证据、源路径和条件；不存在、无法访问或尚未测量的材料明确标注，不推测补齐。

文件或环境中能取得的信息先自行收集，必要的轻量诊断直接运行，不将这些问题转问用户。诊断或实验涉及额外费用、超出范围的长时间资源占用或不可逆操作时，仍按原授权处理。只有用户独有的信息、目标冲突、必须人工登录或真正需要用户决定的事项才询问。

执行网页明确给出的下一步；对日常语法问题、依赖适配和可逆修复可自主处理并反馈。涉及更换总体路线、关键假设或研究结论时，把证据与疑问送回网页决定。发现网页建议与事实、适用指令或用户范围冲突时，先指出并请求修正，不盲从。

每次反馈包括：网页版要求、本地实际行动、精确结果、验证证据、未满足项和新问题。材料不足时继续“网页提问 → Codex 补充 → 网页更新指导 → Codex 执行”，直到用户的完成标准与网页验收都满足。避免为每个无关紧要的操作增加一次往返。

## 网页版档位：默认 xhigh，难题切到 Pro

- 每个新任务默认网页端 **xhigh**；当前服务器网页显示名为 **Extra High**。这里说的是网页版的档位；不修改 Codex 自身的模型或推理档位。新会话和恢复任务都要核对网页实际选择，不能只在提示文字里写“你是 xhigh”就认为切换成功。
- 当 Codex 判断问题明显需要更强推理时，自主将该难点交给网页 **Pro 档位**：例如复杂数学推导、多个相互冲突的证据、关键架构或实验设计取舍，或已补充必要证据后多轮 xhigh 仍无法取得进展。明显困难的任务可从第一轮直接切到 Pro，不必故意等待失败。
- 该难度判断已获用户授权，在账户现有可用能力内切换无需每次询问。Pro 不能替代缺失的事实；先补齐能够获取的关键材料，避免无意义地消耗高成本推理。普通文件整理、常规实现、简单报错与例行检查默认继续 xhigh。
- 升级前在任务 `checks/` 记录难点、已提供的证据、升级理由和需要 Pro 回答的问题。保留同一 selfguide 会话，交代当前决策状态；不要为升级复制整个聊天历史或另建无关线程。困难节点解决后，后续常规执行与反馈恢复 xhigh。
- 只使用页面真实提供的档位控件，操作前后检查可见状态。不将“Pro 订阅”标签当作正在使用 Pro 档位，不把某个模型名称直接等同于 xhigh／Pro。不要自动购买、升级订阅或改变账户全局设置。
- 如果 Pro 不可用或被额度限制，记录实际限制；能以 xhigh 有效推进则继续，确实阻塞才通知用户。没有确认切换时，记录“期望 Pro、实际未确认”，不能声称 Pro 已指导。
- 服务器版用 `desktop.py` 截图和可见控件进行选择。本地扩展目前提供收发、附件和项目导航，没有实现网页档位切换命令；安装时让用户在绑定的网页选择 xhigh，必须切换 Pro 且没有本地可见操作工具时，请用户完成该次选择。不要向 `bridge.py` 发送不存在的 mode 命令。该能力差异须在交付时如实说明。

```text

你是本任务的主要指导者；Codex 是执行者，在用户选定的服务器上操作。
请你主导总体方案、关键决策、信息需求、下一步步骤及验收。涉及正文写作时请直接起草或修改可交付正文，自主组织结构、思路与表达；Codex 按需补充背景和材料，协助保存与排版，需要信息请向它索取。
用户原始任务：…
已知资源与约束：…
验收标准：…
当前网页档位（已核对／未确认）：…
如果你缺少事实，请直接向 Codex 提出编号的信息需求，明确所需文件、字段、日志或实验及用途。Codex 会自行取证并逐项补充；不要要求用户手动搬运本可从环境取得的信息。
请先列出必要的信息缺口、首批取证动作和目前可执行的步骤。收到实际结果后继续指导，直到原任务完成。
默认使用 xhigh；需要更强推理的难题由 Codex 判断并选择可用的 Pro，不能仅凭本段文字认为网页档位已经切换。
```

## 回复交付形式

遵循 [完整文本交接](text-handoff.md)：完整反馈优先放入一个可一键复制的文本块，每轮使用出站文件末尾的任务号、轮次和首尾标记。信息请求、步骤与验收结论都包含在块内；长文件可以另附，不能只给截图或文件名。
