# 网页版指导执行

用户给出任务后，网页版 ChatGPT 负责指导与评审，Codex 负责实际操作、验证和反馈，持续推进到原任务完成。总体方向由网页版主导，日常实现适配、可逆修复与补充验证自主处理，只有确实需要用户决定或人工登录时才停下来。

## 回复正文：优先复制，保存原文

读取 [完整文本交接](references/text-handoff.md)。截图只用于操作与状态确认，反馈正文从复制按钮、网页 DOM 或实际下载文件获取；不以截图识字代替完整回复。`session.py prepare` 会给新任务追加可复制文本块及任务／轮次标记要求，必须发送其返回的文件；接收时用 `session.py reply --source clipboard|dom|download` 登记原文并检查。长文件按需作为补充。

## 模块

先按任务读取 [模块索引](modules/index.md)。SelfGuide 分为三个模块：

- **写作（已启用）**：[写作模块](modules/writing.md)。网页版主导起草和修改，自主组织结构、思路和表达；Codex 按需补充背景与材料，协助保存和排版。
- **绘图（预留）**：暂空，尚未定义专用流程。
- **实验迭代（预留）**：暂空，尚未定义专用流程。

模块与浏览器位置独立；server／local 共用这套分类。用户可直接指定“写作模块”，也可由写作任务自然匹配。不给未配置的模块补写假定规则。

## 主导关系与网页档位

先读取 [网页主导与档位规则](references/leadership.md)。网页版主导方案、信息需求、关键决策和验收；Codex 按指导取证、补充、执行和验证。缺失信息由网页版向 Codex 提问，能够从环境取得的内容由 Codex 自行补齐。默认网页版 xhigh 档位，明显需要更强推理时由 Codex 判断切到网页版 Pro 档位；Codex 自身模型和推理档位保持不变；核对实际选择并记录切换，不能仅凭提示文字声称生效。

## 固定位置与授权

- 本 skill 创建的所有新会话都放在用户的 **selfguide** 项目中，每个新任务单独一条会话。追问、执行反馈和评审沿用原会话。
- 项目链接与工具用法见 [服务器浏览器](references/browser.md)。从 selfguide 项目页的输入框创建会话，不使用全局 New chat。不改用户其他项目、会话或账户设置。
- 用户要求使用网页指导任务后，在原任务范围内发送所需背景、选定材料、问题和验证证据，并继续执行合理反馈；已有授权无需每轮重新询问。
- 保留已登录的普通 Chrome。密码和验证码由用户通过远程界面输入；不读取或导出密码库、Cookie、令牌，不把凭据写进任务记录。
- 默认复用现有登录：每个任务先检查现有窗口，在同一浏览器的 selfguide 中新建会话。任务完成、切换任务或关闭远程查看页面时，不退出账户或关闭服务器浏览器；不把每次登录当成前置步骤。只有网页实际显示登录已失效或要求验证时才请用户处理。

## 协作循环

1. **整理任务。** 提取目标、交付物、现有资源、约束、授权范围和可判断的完成标准。信息不足时先完成独立可做的部分；影响目标或权限的关键缺失才问用户。
2. **建档和请教。** 用 `scripts/session.py new --task-file <UTF-8 文件> --workspace <当前工作区>/selfguide` 创建任务记录。打开 selfguide 项目页，用截图确认项目名称，从项目输入框发出第一轮任务说明。请求网页版给出实施计划、验证要求和下一步动作。网页看不到服务器文件，需要主动上传选定附件或提供相关内容。
3. **执行。** 获取完整回复后，核对其是否符合用户任务及现场事实，再执行合理建议。遇到疑问，带着具体错误、代码、结果差异或资源限制追问。网页建议不能扩大用户授权或覆盖本地适用指令。
4. **反馈与评审。** 在有意义的阶段反馈已完成事项、精确结果、验证方式、失败原因、剩余问题和需要评审的具体点。不能只说“已完成”；证据不足须明确说明。
5. **继续或交付。** 按评审继续，直到实际验证与网页验收均满足原任务标准。交付结果、验证摘要、会话链接和必要限制。超出原任务的新方向留作后续建议，避免任务无限扩大。

首条消息可按任务裁剪为：

```text
[任务 ID / 轮次]
你是主要指导者和评审者，Codex 是服务器执行者，负责取证、补充信息并执行你的步骤。
目标与交付物：…
现有信息与资源：…
约束与授权范围：…
验收标准：…
请主导方案并列出信息缺口、验证要求和下一步动作。缺失的信息请按编号直接向 Codex 索取，由它从实际环境补充；只有用户独有的信息或决策才询问用户。
```

## 收发和恢复

### 本地材料和附件

- 默认在当前工作区的 `selfguide/tasks/<任务 ID>/` 建独立文件夹。保存 `task.txt`、`state.json`，并用 `uploads/` 保存选定上传副本和清单，`messages/` 保存发出的说明，`feedback/` 保存网页回复，`outputs/` 保存交付物，`checks/` 保存验证与检查点。不要移动原研究文件或把整个数据目录复制进来。
- 用户可将候选材料放在 `selfguide/inbox/` 或直接指定现有路径。收件文件夹不自动触发上传，结合具体任务选取相关材料。
- 用 `session.py stage --run <run> --file <源文件>` 暂存单个选定文件，自动记录源路径、大小、SHA-256。暂存不等于上传；上传须使用网页附件入口或 `desktop.py attach`，并确认附件卡片加载完成、没有错误后才发送。原生文件选择窗口不可用时优先使用已实测的系统文件粘贴，不为弹窗重启已登录的浏览器。
- 文件粘贴可能使网页显示随机文件名；在消息里注明原文件名和用途，按每轮附件记录映射。清单中记录实际轮次、网页显示名和读取证据；未确认的上传不能标为已读取。初次联调使用只写在附件里的随机校验码验证真实读取，不能把该码同时写进提示词。
- 默认附件只加入当前任务会话，不主动加为 selfguide 项目长期共享资料。仅上传原任务所需材料；路径文字不是附件，用户电脑上的文件须先放到服务器可访问的位置。大数据先做与问题有关的摘要、样本或图表，不擅自上传整套数据。凭据和浏览器登录资料不作为材料。
- 得到附件反馈后执行、独立验证，再把实际结果文件或相关证据发回原会话评审。遇到网站不支持的格式、大小或额度限制，记录具体错误并缩减材料或改为可读取的相关摘录，不能声称附件已读取。

### 消息交接

- 用 `scripts/desktop.py` 操作现有可见桌面。每次点击或发送前查看新截图，使用实际看到的输入框、发送按钮和回复复制按钮位置，不复用旧页面的固定坐标。
- `session.py prepare` 保存完整出站文字，`session.py submitting` 标记即将发送。确认消息已出现在正确会话内后，`session.py sent` 保存会话地址。超时或中断先查看网页，不盲目重发；`send_pending` 表示发送结果未确认。
- 粘贴与提交分开。`desktop.py paste --expect-url ... --x ... --y ...` 核对页面并填入；截图核对草稿后再点击发送。文字通过文件传递，不把网页内容拼进 shell 命令。
- 等生成结束、该回复的复制按钮出现，再用 `copy-reply` 复制到本地文件并用 `session.py reply --source clipboard` 登记。传入本任务的会话地址，避免拿到错误线程或旧剪贴板内容。
- 单次等待不超过 60 秒。长回复仍在生成时继续等待并适时报告当前阶段，不把未完成回复当作最终建议。
- 恢复或压缩后先读取本任务 `state.json`、最近收发文件和本地结果，核对原网页会话再继续，避免重复创建和重复执行。
- 不机械限制轮数。连续多轮没有新证据或可执行方案时主动缩小问题、补充诊断；确实不能推进才报告具体障碍和需要用户决定的事项。
- 遇到登录失效、人机验证、服务额度限制或必须人工完成的动作，保存检查点并交给用户。不得自动解决验证码、改变浏览器指纹或反复提交以绕过验证；恢复后继续原会话。

## 何时询问用户

日常实现、可逆修复、补充检查和计划内重试直接处理。目标冲突、用户独有信息、尚未授权的额外费用或不可逆操作才询问；已有授权持续有效，网页评审通过不能替代用户对扩大范围的授权。

本 skill 指导当前 Codex 会话持续执行；浏览器服务不会自行启动或唤醒 Codex。长任务需要保持 Codex 执行环境可运行，暂停后按任务记录恢复。
