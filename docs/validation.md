## 服务器浏览器版

原部署已在用户自己的真实 astra 项目做过两轮闭环：TXT 附件包含仅存在于文件中的随机码；网页版读出该码及合成数据并指导生成 JSON；Codex 独立验证后将 JSON 结果作为附件回传；网页版给出验收通过。全过程复用了现有普通 Chrome 登录。

发行包沿用该版本的桌面收发与任务状态逻辑，并移除了用户固定路径及私有项目链接。服务启动代码整理为普通 Chrome 模式，支持系统依赖与用户目录依赖。新打包的服务使用临时空白浏览器、独立显示号和端口做启动检查，不触碰原已登录浏览器。

## 本地浏览器版

已运行真实 Chromium 扩展环境，加载发行包的 service worker 和内容脚本，通过真实 HTTP 桥接连接到受控模拟页面，验证：

- 只读取任务页面最近消息，不收集模拟侧栏历史。
- 附件字节和 SHA-256 校验一致，文件进入网页上传输入。
- 填入草稿后核对文字，再提交，确认本轮消息和会话 URL。
- 读取本轮完整回复，拒绝将之前的回复当成本轮结果。
- 回复后回到项目页，准备下一任务。

**该测试使用模拟页面，未登录真实 ChatGPT；尚未在用户本地电脑运行。** v0.1.0 的本地版作为初版提供，首次安装需在实际 ChatGPT 页面完成合成附件的两轮验收。网页版 DOM 变化可能需要维护 `extension/content.js`；本地系统、浏览器后台节流、SSH 可达性和网站登录状态仍需现场确认。

## 自动检查

Python 测试覆盖桥接鉴权、角色隔离、拒绝外部网页 Origin、同一命令只领取一次、结果确认幂等、未确认操作恢复、过期命令、项目边界、附件完整性，以及两个 skill 的任务目录、附件来源、禁止覆盖、发送状态和暂停恢复。

两个 skill 通过 skill-creator 的结构检查；Python 与 JavaScript 通过语法检查。发行包采用明确目录清单生成，解压后在临时目录测试安装，避免依赖当前工作区的绝对路径。

## 边界

没有承诺永不重新登录或绕过人机验证。本地扩展不会自己启动 Codex，本地电脑、浏览器和 SSH 隧道需要保持运行。服务器版新环境需要系统依赖；现有服务器浏览器保持登录不等于所有新服务器均已验证。桥接默认单文件 8 MiB 不是网站官方限制。
